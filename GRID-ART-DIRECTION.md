# Portfolio art direction: engineering casebook

## Core idea

Present Kunal's software as a compact, book-like casebook. The projects lead;
the editorial system gives them rhythm and a consistent reading path.

Use the magazine reference for its oversized portfolio masthead, tiny running
labels, bracketed project numbers, thin rules, and carefully aligned columns.
The reference image itself is not a site asset.

## Page structure

- One continuous white reading page with a shared content measure.
- A simple running header, concise introduction, selected project studies,
  competition wins, interests, about, and contact.
- Every project follows the same vertical sequence: title and purpose, an
  optional project visual, overview, engineering note, technologies, and
  verified links.
- Use rules, alignment, type scale, and whitespace for hierarchy. Do not turn
  each text block into a separate card.

## Grid use

- Keep the AVIF grid at its original contrast and let it scroll with the page.
- Show it in the page margins and in project visual areas.
- Keep paragraphs, navigation, and metadata on the uninterrupted white page.
- Align project graphics, captions, and rules to the same content column.
- Avoid offset shadows and colored backing slabs.

## Palette and type

- White canvas, jet-black structure, electric-orange emphasis, restrained
  cobalt details.
- Archivo Black for a few display moments; Space Grotesk for reading and
  interface text.
- Let actual project media carry its own product colors. Label representative
  UI mockups honestly; never describe them as device screenshots.

## Content integrity

- Project facts come from local project documentation and source.
- Render only verified repository and demo URLs.
- The brief confirms three competition wins, but names, placements, dates, and
  evidence links remain unavailable and must not be invented.
- No fake volume metadata, empty counts, testimonials, or placeholder contact
  details.
